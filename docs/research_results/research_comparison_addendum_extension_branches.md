RESEARCH COMPARISON ADDENDUM: EXTENSION BRANCH COMPARISON

Purpose

This document extends `docs/research_results/research_comparison.md` without modifying it.

Its purpose is to compare extension branches explicitly, because the project now has many legitimate future directions and one of the main risks is letting them blur into the core too early.

This document does not promote any extension to core status.


SECTION 1. EXTENSION-BRANCH-SPECIFIC COMPARISON METHODOLOGY

Extension branches are compared using the master framework plus these specific factors.

Additional measured factors used here

1. Core-question relevance
- how directly the branch helps answer the main market-only versus event-state question

2. Scope-drift risk
- how likely the branch is to drag the project away from its current thesis identity

3. Benchmark-family disruption risk
- how likely the branch is to force hidden benchmark-family change

4. Optionality quality
- how easy it is to cleanly add or remove the branch without breaking everything else

5. Learning-value density
- how much new understanding the branch may provide relative to its implementation burden

6. Documentation burden
- how much extra explanation, caveat management, and thesis-writing burden the branch creates

7. Data fragility
- how much the branch depends on fragile data availability or point-in-time assumptions

8. Long-run value
- how valuable the branch may become after the thesis core is already stable

SECTION 5. SIMILARITY NOTES FOR EXTENSIONS

- Dynamic company profiles, graph branches, and broad mainstream-news branches are all close in one crucial way: they look attractive conceptually but score poorly on current benchmark integrity and engineering fit.
- Static company metadata and stronger frozen finance encoders are the cleanest high-value later additions under current repo maturity.
- The derivative appendix branch and regime-aware branch are not similar in conceptual purpose, but they are both acceptable late-stage comparators if their benchmark families remain narrow and explicit.


SECTION 6. NON-DECISION SUMMARY FOR EXTENSIONS

This addendum does not decide which extension should be done first.

What it shows clearly is:
- some extensions are broadening in a clean way
- others are broadening in a scope-breaking way
- static metadata and stronger frozen encoders are clean later additions
- dynamic profiles, broad news expansion, graph-heavy redesigns, and early fine-tuning remain structurally risky
- derivative experiments are acceptable only as narrow late appendix families
